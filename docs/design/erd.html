Relasi utama

  • users 1—* medications — obat milik satu pasien (owner_id).
  • medications 1—1 medication_frequency — satu pola minum per obat.
  • medications 1—* medication_times — jam konkret (pagi/siang/malam atau jam:menit).
  • medications 1—* medication_logs — catatan minum. Kunci unik (obat, jadwal, tanggal, jam:menit) menggantikan tabel slot; schedule_id NULL untuk dosis PRN/spontan.
  • medications 1—* medication_dose_events — penyimpangan (missed, dose_shift, paused), append-only.
  • medications 1—* bump_queue — hanya pekerjaan yang akan datang (snooze, job notifikasi, refill, digest).
  • Tidak ada tabel slot. Tanggal dosis dihitung dari aturan (medication_frequency + medication_times) saat dibutuhkan.
  • medications 1—1 medication_stock 1—* stock_transactions — stok berjalan + riwayat transaksi.
  • users *—* users via care_links — owner_id (pasien) dan caregiver_id (pemantau), berstatus.
  • users 1—* notification_prefs | device_tokens | user_integrations | refresh_sessions.
  • notification_jobs 1—* notification_deliveries — satu baris per kanal per job.
  • audit_log mencatat actor_id + owner_id tanpa FK ke sumber daya (log tetap utuh setelah objek dihapus).
PK primary key FK foreign key UQ unik / partial unique GEN generated column TRG diisi trigger

Catatan desain

  • Pola frekuensi — daily (× per hari), interval (tiap N jam), weekly (bitmask hari), monthly_cycle (intake N hari lalu pause M hari; atau tanggal tertentu / akhir bulan), prn (bila dibutuhkan).
  • Satuan — mengacu UCUM subset di ref_unit: mg, g, mcg, IU, mL, tetes, puff, spuit, tablet, kapsul, unit, olesan. Satuan kombinasi lewat strength_note (mis. 120mg/5mL).
  • Cara pakai — meal_relation (sebelum/sesudah/saat makan), as_needed, must_finish, dan notes_reminder bebas.
  • Stok — balance_after diisi trigger apply_stock_txn(); saldo negatif ditolak di aplikasi dan di DB. Peringatan restock saat current_qty <= refill_threshold_qty.
  • Katalog — drug_catalog dipakai dua tahap. Tahap 1 (sekarang): cukup untuk input manual user; kolom penyedia boleh kosong. Tahap 2: importer KFA/BPOM mengisi kfa_code/bpom_nie + extra_meta, jadi penyedia baru tidak butuh migrasi. FK dari medications memakai id internal (UUID), bukan kode penyedia.
  • Anti log ganda — uq_log_occurrence partial unique pada (medication_id, schedule_id, slot_date, scheduled_hour, scheduled_minute) untuk baris hidup.
  • Jadwal tanpa row per hari — terapi seumur hidup tetap 1 baris pola + N baris jam. Biaya storage tumbuh hanya saat dosis benar-benar dicatat, jadi tidak membengkak di skala SaaS.
  • Preset vs data user — drug_catalog.owner_id NULL + is_preset = katalog publik kurasi admin; owner_id terisi + curation_status='user_private' = katalog pribadi user dan tidak pernah masuk preset.
  • User vs admin — users.role (user / admin), terpisah dari is_active. admin_scope subset {users, catalog, notifications, reports}, NULL = penuh. Peran hanya ditetapkan lewat DB/seed, tidak ada endpoint yang menerimanya dari klien.
  • Audit admin — actor_role disalin saat aksi (agar jejak tidak berubah bila peran user berubah), plus before_state/after_state untuk perubahan sensitif. Aksi admin: admin_grant, admin_revoke, admin_scope_change, user_disable, user_enable, user_erase, catalog_publish, catalog_import, retention_purge, dan sejenisnya.
  • Nilai enum berbahasa Inggris — semua CHECK memakai istilah Inggris (mis. after_meal, evening, child), sedangkan name di tabel ref_* tetap Indonesia karena itu label tampilan untuk user.
  • Waktu — semua absolut TIMESTAMPTZ; slot_date dihitung backend dari users.timezone, bukan zona DB.
  • Soft delete — semua query aplikasi wajib WHERE deleted_at IS NULL, kecuali laporan admin.
